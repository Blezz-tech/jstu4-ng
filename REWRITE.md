# jstu4 v2.3 → v3.0: что и почему переписано

Короткий отчёт по миграции исходного проекта (2011–2016, jQuery 1.6.4) на
стек 2026 года. Код — в `jstu4-modern/`, рядом с оригиналом.

## Итог

| Метрика             | v2.3                                            | v3.0                                                               |
| ------------------- | ----------------------------------------------- | ------------------------------------------------------------------ |
| Рантайм-зависимости | jQuery 1.6.4, HotMilk/Milk, `jquery-plugins.js` | **0**                                                              |
| JS в поставке       | ~280 КБ несжатых, из них 238 КБ — jQuery        | **32.5 КБ** (11 КБ gzip)                                           |
| Языки               | ES3-стиль, глобальные `i18n`, `TM`              | TypeScript strict, ES-модули, `noUncheckedIndexedAccess`           |
| Типизация           | нет                                             | 100% кода, `tsc --noEmit` в CI-скрипте `build`                     |
| Тесты               | нет                                             | **35 юнит (Vitest) + 16 сквозных (Playwright)**                    |
| Линт/формат         | нет                                             | ESLint 10 (typescript-eslint, type-checked) + Prettier             |
| Сборка              | ручное подключение `<script>`                   | Vite 7, хешированные ассеты, sourcemaps                            |
| Доступность         | кнопки-ссылки без семантики                     | `<button>`, `<dialog>`, aria-live, `:focus-visible`, skip-link     |
| Темы                | нет                                             | светлая/тёмная/системная, `color-scheme`, `prefers-reduced-motion` |
| Адаптив             | фикс. `max-width: 800px`                        | flex/grid, `clamp()`, мобильный layout                             |
| Сохранение          | нет                                             | `localStorage`: программа, лента, язык, тема, звук                 |

## Сопоставление файлов

| Оригинал                                                 | Куда переехало                                                                      |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `tu4.js` (TM, TMRun, TM.Command, TM.compile)             | `src/core/{machine,parser,program,run,tu4,errors}.ts`                               |
| `i18n.js`                                                | `src/i18n/{ru,en,types,index}.ts`                                                   |
| `ui.js`                                                  | `src/ui/controller.ts` + `src/ui/render.ts` + `src/main.ts`                         |
| `hotmilk.browser.jquery.js` (Milk-шаблоны)               | шаблонные функции в `i18n/*.ts`                                                     |
| `jquery-plugins.js` (placeholder, scrollTo, selectRange) | платформенные API: `placeholder`, `scrollIntoView`, `setSelectionRange`             |
| `jquery-1.6.4.js`                                        | — (не нужен)                                                                        |
| `jstu4.html`, `jstu4.css`                                | `index.html`, `src/styles/main.css`                                                 |
| `help-ru.html`, `help-en.html`, `help.css`               | `<dialog id="help-dialog">` + `i18n.help` (старые URL → заглушки в `public/jstu4/`) |
| `jstu4-{ru,en}.html`                                     | `?lang=ru` / `?lang=en` (+ заглушки в `public/`)                                    |

## Ключевые решения

1. **Ядро — чистые модули без DOM.** `MachineRun` хранит ленту в массиве
   односимвольных ячеек, состояние и позицию; шаг — единственная мутация.
   Поэтому машину можно тестировать в Node без jsdom, а UI вообще не знает,
   как устроен прогон — он вызывает `step()` и рендерит снимок.

2. **Совместимость важнее «идеальной» семантики.** `01` ≡ `1`, комментарии
   `#`/`//`, ограничение ленты слева, начальное состояние `0` при запуске,
   «ненормальность» (затёртый источник / головка не после результата) —
   перенесены один в один и закреплены тестами, включая курьёз с примером
   из справки.

3. **Без `innerHTML` на пользовательских данных.** В оригинале программа и
   лента собирались склейкой строк с ручным `&lt;`/`&gt;`. Теперь — узлы
   `createElement` + `textContent`; трава `charToHTML` больше не нужна.

4. **Реактивность без фреймворка.** Статический каркас в `index.html`, всё
   состояние — в `AppController`, DOM-обновления точечные: у выполненной
   команды меняется класс `current`/`visited`, у ленты перерисовывается
   только строка ячеек. Полной перерисовки страницы нет.

5. **Ядро ошибок на классах `Error`.** `instanceof` работает нативно, без
   трюков с `prototype = new Error()`; у каждой ошибки есть типизированные
   `data`, которые использует i18n.

6. **i18n — типизированные словари.** Никаких глобальных `i18n['en'].texts`,
   `$('#selector')` в строках и шаблонов с `$T`. Функции сообщений принимают
   параметры по типам, справка — структурированные блоки (p/list/code), а не
   HTML-разметка в JS.

## Найденные и исправленные дефекты оригинала

- Два определения `charToHTML`/склейка HTML — XSS-поверхность на поле ленты.
- `stateKey`-коллизии: в `tu4.js` ключи объекта `program[cmd.q()]` совмещали
  числовые и строковые имена состояний (в JS `1` и `'1'` — один ключ).
- `setInterval` с частотой, которую контролирует пользователь, мог «догонять»
  очередь в фоновой вкладке; теперь — `rAF`-цикл с отменой по поколению.
- Ошибки `TM.*Error` не наследовались от `Error`, не имели `message`.
- Кнопки Enter/Space в режиме выполнения перехватывались глобально, включая
  нажатия на самих кнопках (в v3.0 сначала срабатывает действие контрола).

## Как проверить

```bash
cd jstu4-modern
npm install
npm run check      # lint + prettier + 35 юнит-тестов + сборка
npm run test:e2e   # 16 сценариев Playwright в Chromium
npm run dev        # живой предпросмотр
```
